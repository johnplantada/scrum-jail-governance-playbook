# Governance Playbook 1.0 — remediation catalog

Audit and repair date: 2026-08-02. This maintainer artifact records why the mutable
workspace implementation was rejected and what now carries each guarantee. It is not
vendored into generated organizations.

## Prior “resolved” claims that were falsified

The earlier resolutions below are historical and must not be used as evidence. They relied
on agent-writable scripts/configuration, prompt hooks, incomplete command-prefix coverage,
or provider-native workers. The 1.0 repair removed those mechanisms instead of preserving
compatibility.

### OPS-003 — incomplete GitHub state could become deletion or closure

The earlier exception-only monitor fix did not cover every read, page, and derived absence.
It is superseded by independent source snapshots in `control/sjg_control/delivery.py` and
tri-state planning in `control/sjg_control/reconcile.py`. Pages are persisted without
advancing a checkpoint; their events remain staged and unrouteable until a complete snapshot
atomically publishes them and advances. Any incomplete observation is `UNKNOWN`, and
`UNKNOWN` plans no mutation. Workspace monitor files are operator shims only.

Required regression: fail every page position for every source and prove no checkpoint,
close, move, create, or duplicate delivery occurs.

### PROVIDER-001 — headless provider networking and configuration were brokered

The earlier claim depended on mutable project config and excluded command forms. It is
superseded by `control/sjg_control/provider.py` plus installed provider policy. Agent process
network is deny-all; GitHub access occurs only in the controller. The environment is an
allowlist with a supervisor-owned home and no provider/GitHub key, proxy, config-directory,
shell-startup, or Git override. Codex native multi-agent/apps/hooks are off and direct
network/GitHub/provider commands are forbidden as defense in depth. Claude settings fail
closed, have no excluded commands or unsandboxed escape, disable bypass/auto modes, and a
per-wake generated settings file permits only that wake’s broker socket.

Required regression: validate real supported CLI versions/status shapes, execpolicy direct
forms, shell-wrapped forms under OS network denial, settings precedence, sandbox absence,
and alternate provider/API-key environment variables.

### GOV-004 — Human Principal commands were protected by hooks and prefix rules

The earlier `authority_gate.py` and command rules could be bypassed by alternate transports
or workspace edits. They were deleted. `control/sjg_control/authz.py` now exposes a closed
agent operation set that does not contain objective mutation, PR merge/auto-merge, workflow
dispatch, deployment, spending, governance activation, repository settings, branch deletion,
or force update. `github_backend.py` constructs fixed operations and never accepts raw URLs,
methods, GraphQL, commands, credentials, repositories, or branch roles. Generated clients
have no credential or direct remote Git path.

Required regression: send every Human-only operation and objective disguise through the
broker, including raw authority fields, issue-closing PR text, protected paths, and stale or
incomplete facts; all must be denied before backend execution.

### GOV-005 — Codex built-in workers were bounded by project overrides

Project-local overrides are not a security boundary and were removed. Native provider
multi-agent tools are disabled/denied. `control/sjg_control/workers.py` is the only worker
path: named types, server-selected Luna model/tools, cumulative and concurrent transactional
caps, disposable scratch, declared paths, bounded output, no broker socket, and no recursive
worker capability.

Required regression: zero-cap roles cannot start one worker, cap+1 is refused after earlier
workers finish, simultaneous cap is atomic, non-implementers cannot write, undeclared changes
are not imported, and model/provider/socket overrides are denied.

### GEN-003 — role validation and path containment were sufficient

Kebab-case custom roles still contradicted the clean-break roster, and path checks did not
cover the whole output transaction. `bin/orggen` now permits exactly the four required roles
plus optional `policy-reviewer`, rejects duplicates/missing/custom roles, requires a new target
outside the golden, excludes ignored inputs, rejects symlinks, stages in a sibling directory,
validates structured output and roster surfaces, records file modes/hashes, and renames only
after success. `organization.yaml` binds the required immutable control release.

Required regression: traversal, hostile scalars, duplicate/missing/custom roles, optional
policy reviewer, ignored/symlinked inputs, late validation failure, existing targets,
executable modes, provenance, installation, and organization-bound activation.

## Other repair decisions

- Removed workspace provider launch, native-worker policy, budget/closure authority, runner
  cursors/spools, direct-push implementation, dashboard model chat, stale delivery predicates,
  and compatibility terminology paths.
- Replaced `pm-gh.sh`, `git-push-branch.sh`, runner, monitor, and agent-run with thin clients
  that fail closed when the installed controller/socket is absent.
- Added source/payload provenance, immutable install, Human-only atomic activation, manual
  Human-guarded workflows, exact action pins, and credential-separated preview build/deploy.
- Kept `github-pm-setup.sh` only as an explicitly Human commissioning tool.
- Chose no LangChain dependency. A2A remains permissible only as an unprivileged edge adapter,
  never as an authority or transport passthrough.

## Verification policy

A green suite is evidence, not proof. Release evidence must include the full working-tree diff,
a fresh `--allow-dirty` development stamp, its complete `make test`, control and generator
tests, Python compilation, ShellCheck at error severity, `git diff --check`, Codex execpolicy
checks, Claude settings validation, and read-only provider authentication/status checks. Do
not perform live GitHub mutations, workflow dispatches, deployments, or spend-provider smoke
tests as part of verification.
